# Agent Support Matrix — every agent, one flat discovery layer

How this library guarantees every skill is natively discoverable by **every** agent that
speaks the open Agent Skills format (`SKILL.md` + `scripts/` + `references/` + `examples/`),
based on the ecosystem's agent-directory mapping (skills.sh / vercel-labs `skills` CLI
supported-agents table and the `.agents/skills` universal convention).

## The one structural fix that matters

Agent skill scanners look for `<skills-dir>/<name>/SKILL.md` at **one level of nesting**.
Our canonical store is two levels deep (`skills/<domain>/<name>/SKILL.md`), which native
scanners would not descend into. Fix: a committed **flat discovery layer** —

```
skills-flat/<name> -> ../skills/<domain>/<name>     (one symlink per skill, whole skill dirs)
```

`skills-flat/` is generated by `scripts/build-flat-index.sh`, checked in, and what every
installer links. `references/`, `scripts/`, `examples/` keep resolving because the whole skill
directory is symlinked, not just `SKILL.md`. Invariant enforced: one entry per skill, no duplicate
names, no broken links (see "Verify" below).

## Discovery layout (canonical, 2026)

| Agent | Project scope | Global (user) scope | Notes |
|---|---|---|---|
| Universal (Codex, Cursor, Gemini, Copilot, OpenCode, Cline, Zed, …) | `.agents/skills/` | `~/.agents/skills/` | shared cross-agent home |
| Claude Code | `.claude/skills/` | `~/.claude/skills/` | **does NOT read `.agents/skills/`** — always link here too |
| GitHub Copilot | `.agents/skills/`, `.github/skills/` | `~/.copilot/skills/` | VS Code also reads `.github/skills/`, `.claude/skills/` |
| Cursor | `.agents/skills/`, `.cursor/skills/` | `~/.cursor/skills/` | prefer **copies**, not symlinks (symlink-discovery bug) |
| Codex | `.agents/skills/`, `.codex/skills/` | `~/.codex/skills/` | universal |
| Gemini CLI | `.agents/skills/`, `.gemini/skills/` | `~/.gemini/skills/` | `@skill` attach in prompt |
| Windsurf | `.windsurf/skills/` | `~/.windsurf/skills/` (Codeium) | native (non-universal) |
| Cline | `.agents/skills/`, `.cline/skills/` | `~/.cline/skills/` | hooks support (with Claude Code) |
| OpenCode | `.agents/skills/`, `.opencode/skills/` | `~/.config/opencode/skills/` | universal |
| Zed | `.agents/skills/` | `~/.agents/skills/` | rules live in `.rules/`, skills per standard |

Sources: vercel-labs/skills "Supported Agents" + agent-config reference; Adobe Agent Skills
ecosystem overview; community skill-installer registries (j-skills, skillex, magpie). Treat the
agent→dir map as convention that moves slowly but does evolve — the matrix above is the
conservative union (universal + agent-specific relays).

## What we link (scripts/install.sh, project scope via skills-init)

```
agents     -> <home or project>/.agents/skills
claude     -> <home or project>/.claude/skills
copilot    -> <home or project>/.copilot/skills   (global) / .github/skills (project)
cursor     -> <home or project>/.cursor/skills
codex      -> <home or project>/.codex/skills
gemini     -> <home or project>/.gemini/skills
windsurf   -> <home or project>/.windsurf/skills
cline      -> <home or project>/.cline/skills
opencode   -> <home or project>/.opencode/skills
```

All point at `…/skills-flat`. Installer never clobbers an existing non-symlink skills dir that
already has content (skips with a notice).

## Verify (after any install or rebuild)

```bash
scripts/build-flat-index.sh        # regenerate; prints "<N> skills linked"
python3 scripts/check-flat-index.py    # invariant check: count, collisions, broken links
# then: one entry per skill, no duplicates, every <name>/SKILL.md resolves
```

Then confirm per agent, e.g. Claude Code: `/plugin` or skill list shows entries; Gemini CLI:
`@` completion lists skills; any universal agent reading `.agents/skills` sees one name per skill.

## Portability caveats (documented, not hidden)

- **Claude Code ignores `.agents/skills/`** — the `.claude/skills` relay is mandatory.
- **Cursor historically ignores symlinks** — use copy mode there (`skills.sh` CLI `--copy`, or
  `skills-init --copy` once added).
- Advanced fields are not universal: `context: fork` (Claude-only), hooks (Claude Code, Cline),
  `allowed-tools` (unsupported by Kiro/Zencoder).
- Windows: symlinks need Developer Mode/admin — fall back to junctions/copies.
- Skill **bodies** are standard `SKILL.md`; anything agent-specific stays in optional hooks
  (`hooks/`) that non-supporting agents simply ignore.

## Where this is enforced

- `scripts/build-flat-index.sh` regenerates the layer; committed output is reviewed in CI.
- The one-entry-per-skill flat-resolvability invariant is re-checked on every change to the skill tree.
- Docs: this matrix + `docs/distribution-best-in-class.md` (skills.sh registry) +
  `docs/plugin-marketplace-publishing.md` (Claude plugin packaging).
