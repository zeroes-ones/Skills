# Healthcare Security Error Decoder

| Symptom | Root Cause | Fix | Lesson |
|---------|-----------|-----|--------|
| OCR breach: patient file uploaded HHS receives notification from random entity | Patient-facing portal accepts unprotected file uploads, PHI not OCR-scanned, files stored in plaintext accessible bucket | OCR all uploaded files. Automatically redact MRNs, SSNs from attachments. Never store uploads in public buckets. Add content-scanning pipeline before storage | File upload is PHI ingestion. Treat uploaded documents like database records — encrypt, access-control, and audit |
| FHIR endpoint returns all patient data regardless of scope parameter | SMART on FHIR token validation only checking token validity, not scopes. `patient/*.read` scope silently granted full access | Validate each scope against requested resource. Reject access if scope doesn't match. Test: request Patient data with only Observation scope — must deny | Token validity != authorization. Always validate scopes against every FHIR resource request |
| Decommissioned server returned to leasing company with PHI on disk | Asset disposal process doesn't include PHI sanitization check. Server disks weren't crypto-erased before return | Add PHI sanitization step to decommissioning checklist. Use NIST 800-88 crypto erase or physical destruction. Certificate of destruction for audit | Decommissioning is a PHI data flow. Every retired server, drive, and backup tape needs documented sanitization |
| Medical device firmware update bricked devices — no rollback possible | No cryptographic signature verification on firmware. Corrupted update applied without validation checksum | Implement signed firmware updates with Ed25519 signatures. Store last-known-good firmware for rollback. Validate checksum before applying | Firmware is code. Treat it with the same security controls as production deployment |
